    ProvostXInference — Architecture (as-is)

    C/C++ inference engine + C# bindings for ProvostX. A llama.cpp-only, GGUF-only execution substrate: the vendored llama.cpp tree is linked directly behind a flat C API, P/Invoked from a strict-OOP C# layer. Replaces LLamaSharp entirely — full control over batching, KV cache, vision, speculative decoding, and backend safety. ProvostXLLM consumes this library in-process and knows only this API — never llama.cpp, ONNX, or any engine internals.

    Dependency flow is strictly one-directional: callers touch only the Engines facade; the facade composes backend adapters into one uniform engine object; nothing below leaks upward.

    Per-engine audit + telemetry (ABI v9, owner order 2026-10-22)

    Append-only wave: pvx_model_params_t gains audit_path + audit_include_prompts (zeroed struct = disabled, bit-identical loads). The audit sink is PER-MODEL — own FILE* + own mutex, opened at load, closed at free; NEVER process globals (an LLM array of engines yields one audit trail per engine instance). Events are JSON lines (ts, monotonic seq, event, optional detail), flushed per line (survives hard kill): model_loaded/model_freed, context_created/freed, spec_enabled/disabled, kv_cleared/kv_shifted. Prompt TEXT is never recorded — token counts only when audit_include_prompts=1 (audit must not become a content sink). Model-wide telemetry counters ride the same struct (plain int64 bumps at the existing commit sites under the infer mutex) and are exported via pvx_engine_telemetry (pvx_engine_telemetry_t: prompt/decode/committed tokens, spec drafted/accepted, errors, contexts alive). ZERO COST when not configured: every counter bump and file write is gated behind audit.enabled — an unconfigured engine executes one branch per commit and nothing else (owner directive 10:42). Rates are derived by the caller between two snapshots; the native side stays stateless.

    Config-surface parity (ABI v8 wave 5) — full llama.cpp config verbs

    Every llama.cpp configuration verb is reachable from C# (engine structs → P/Invoke → facade configs). Wave-5 fields are APPENDED ONLY — a zeroed struct is bit-identical to the pre-wave-5 load (proven: native suite 48/48, ngram 25/25, stress 31/31 with zeroed wave-5 everywhere; C# 230/230). Zero-value semantics: model/context ints and floats at 0, bools false, and null kv-override lists mean "llama default" — the native side maps them to upstream defaults, never to a literal zero override. Knobs whose llama default is TRUE (use_extra_bufts, offload_kqv, op_offload, swa_full, kv_unified, no_perf) use a tri-state int: 0 = llama default, 1 = force on, 2 = force off — a plain bool could not express "unset". kv-override tag mapping: upstream llama_model_kv_override_type order is INT/FLOAT/BOOL/STR; the pvx ABI uses 0=bool, 1=int64, 2=f64, 3=str — mapped explicitly at the native boundary (never by enum order). Seed: <=0 = time entropy (llama default), >=1 = deterministic sampling. Wave-5 samplers run inside pooled_selection_chain in OpenAI-parity order: penalties (repeat/present/frequency) → logit_bias → dry → top_k → typical_p → top_p/min_p → top_n_sigma → xtc → mirostat 1/2 (mirostat bypasses top_p when active) → dist(seed). Facade pass-through: GgufEngineRequest(Builder).WithAdvanced(ModelConfig?, ContextConfig?) carries the extended knobs; classic With* fields always win in the merge, so existing callers are unchanged. ABI sizeof pins (Release, osx-arm64): pvx_model_params_t = 72, pvx_context_params_t = 112, pvx_sampling_params_t = 112 (incl. wave-5 sub-struct pointer), pvx_sampling_params_wave5_t = 72, pvx_logit_bias_t = 8, pvx_kv_override_t = 288 — pinned by PvxAbiSizeTests (C#) and probed at build time.

    Embeddings — architecture-routed

    Routing is by the model's own architecture (llama_model_has_encoder/has_decoder); typed NOT_SUPPORTED when a model exposes neither. Encoder models (MiniLM) use llama_encode; causal models decode and mean-pool. Decoder-only models whose output head differs from the hidden state (merged multi-token heads, e.g. n_embd_out ≠ n_embd) fail closed with a typed NOT_SUPPORTED before any decode. The extraction path fails closed if no embedding source produces data — never zeros dressed as an embedding.

    Grammar (GBNF)

    Persistent grammar chain on executor/conversation; grammar FIRST in the sampler chain; sampled token accepted once at commit (EOG/control skipped). Prompt tokens are NOT grammar-accepted (a per-token accept hook desyncs the stateless feedback loop — removed). Known upstream llama.cpp issue: llama_grammar_accept can crash on multi-character tokens spanning rules with optional whitespace. Mitigation is structural, not a catch-handler: the grammar section runs TIERED REJECTION SAMPLING (tier 1 single-token validation → tier 2 top-k mask → tier 2.5 top-256 mask → tier 3 full grammar-first mask) and every returned token has passed a grammar check before accept() is ever called — there is NO path that yields unconstrained output, and accept() only ever sees a validated token.

    Rewind / hybrid-memory guard

    All partial rewinds check llama_memory_seq_rm's return and answer PVX_ERR_REWIND_UNSUPPORTED on refusal (hybrid/recurrent archs cannot take partial erasure) — counters untouched, no corruption. Full-range rewind still works everywhere. pvx_model_partial_rewind_supported surfaces the capability (C#: IInferenceModel.PartialRewindSupported).

    Backend probe & safety (pvx_backend.cpp)

    Per-CONTEXT probe state (pvx_context_s::backend — never process-global). Detection skips CPU-class devices and matches stable vendor-tag device ids (MTL/Metal, CUDA, Vulkan); an unrecognized accelerator reports its raw device name instead of lying "CPU". All seven pvx_backend_* queries take pvx_context_t* (null-safe) and are re-run by pvx_probe_backend. GPU-layer profile fields (Effective/Original/ReducedGpuLayers) are filled on every facade path.

    Safety layer intervenes only on probe failure: minimal 1-token decode probe validates config; progressive fallback gpu_layers N → N/2 → 0 (pvx_create_context_safe); Vulkan stale-KV flush after pool return (upstream #26744). On total fallback failure the caller's original gpu_layers is reloaded; if even that fails, *model is null and is not freed.

    Concurrency & lifetime

    • infer_mtx on every context serializes all llama_* work; KV-mutating conversation ops (rewind/reset/shift/export) and pool-return hold the SAME lock in a fixed order (pool → infer) as lease — no inverted lock pairs.
    • pvx_state_save clears the backup seq before copying (seq_cp MERGES).
    • Backup mechanism (implemented 2026-10-20, seq1-free): save-state arms by slot budget. With n_seq_max >= 2 it copies seq0 → seq1 (llama_memory_seq_cp) and restore copies back after a seq-0 clear — cheap cell-level copy, but it spends a sequence slot and halves per-sequence capacity (n_ctx_seq = n_ctx/n_seq_max). With n_seq_max == 1 (the LLM seq_max knob AUTO=1 full-context posture) the save now BYTE-SERIALIZES the seq-0 state instead (llama_state_seq_get_size / get_data — cells + K/V rows — held in pvx_state_s::kv_bytes) and restore replays it via llama_state_seq_set_data after the seq_rm clear. One full-state copy at save time buys save/rewind at full per-session context; the old typed PVX_ERR_NOT_SUPPORTED refusal is gone. (Verified 2026-10-20: llama-level roundtrip is byte-identical and logit-exact on CPU and Metal, q8_0/F16 KV; journey SingleSlotSaveRewindJourneyTests pins the recall.)
    • Model destruction ordering: per-model active_context_count + condition variable; pvx_free_model blocks until all its contexts are freed (prevents Metal device-before-buffers aborts); contexts of different models free concurrently.
    • Vision: a second mmproj load is refused while a wrapper is alive (refcounted shared mtmd context — the model waits for wrapper release before freeing it). A failed pre-image text flush in pvx_executor_prompt_with_images is a typed decode failure with pending tokens kept for retry — image embeddings never land at wrong positions.

    Errors & logging

    Every failure path sets a typed result + reason string: context-scoped pvx_last_error, model-scoped pvx_model_last_error (ABI v5 — model-level calls must NOT pass a model handle to the context-scoped function). PVX_LOG structured logging: zero-overhead when disabled (null callback check), levels DEBUG/INFO/WARN/ERROR/NONE, set via pvx_set_log_callback + pvx_set_log_level; C# bridge pins the delegate.

    Per-handle backend dispatch (engine selection)

    ModelConfig.Engine picks the specialist (metal = macOS only; cuda/vulkan = Windows/Linux only). PvxEngineSelector + PvxEngineFileResolver validate fail-closed — unknown/empty/wrong-OS pairs refuse, never fall back. The native-dir RID is ARCH-AWARE on Linux and Windows: IOSProbe.Architecture() (injectable seam; SystemOsProbe reads RuntimeInformation.ProcessArchitecture, test doubles override) drives the resolver (linux-arm64/linux-x64, win-arm64/win-x64); the PvxNative static ctor derives the same from ProcessArchitecture in the bootstrap context (no injectable seam exists pre-activation); macOS stays osx-arm64. Per-RID payload story (BL-49): NO native binaries are checked in — every RID slice (osx-arm64 metal + generic, win-arm64 cpu generic, win-x64/linux-x64 cuda+vulkan) is built by the CI specialist matrix at NuGet-pack time. This keeps compiler-baked build paths out of the repository (anonymity rule — MSVC/ld embed absolute paths in debug strings); local payloads remain gitignored working-tree artifacts for VM testing only. linux-arm64 has no CI payload — source-build the native engine (cmake) and ONNX Runtime for arm64 (no official ORT arm64 payload exists); the resolver looks in runtimes/linux-arm64/native/ for the source-built artifacts. PvxEngineHandle.Open: resolve file → load image → resolve per-image entry-point tables → ABI handshake → router bundle; the process-wide PvxDispatchRegistry routes only the activation-window DllImports (steady-state calls go through per-handle tables). Ownership chain is constructor-injected: Model → Context → Pool/Executor → Conversation.

    Stall-safe chunked prefill layer

    Engine-level, backend-independent, above the native seam (no ABI surface): ChunkedStallSafePrefillRunner commits PromptTokens in chunks over IConversationPool, timing each with IChunkWallClock (wall-clock is the sole mechanism — no backend hooks). RollingPrefillStallDetector: stall = chunk wall > GapMultiplier × rolling median of the baseline window; stalled walls never enter the baseline. StallRecoveryLadder: FreshSlotRetry (smaller-chunk retry halves to the floor) → SmallerChunkRetry → DraftDisabledRetry (via injected ISpeculationSuspender, idempotent native teardown) → FailLoud. Budget exhausted = typed PrefillStallUnrecoveredException carrying chunk index, walls, baseline, steps. Watchdog disabled = single plain commit, zero overhead. Config: stall_watchdog section (fail-closed Validate).

    CI / NuGet policy

    Windows (MSVC) build portability

    The native tree builds under MSVC (VS 2022, ARM64 and x64) with a fixed portability set: explicit <functional> include (libc++ transitive, MSVC not), localtime_s under _WIN32 (POSIX localtime_r), no designated initializers at /std:c++17 (lambda-built constant), no raw strings inside the ASSERT macro stringize path, _USE_MATH_DEFINES for M_PI, WINDOWS_EXPORT_ALL_SYMBOLS ON (no dllexport in the extern "C" header — restores the macOS-parity export surface + import lib), and WIN32 test executables link llama/ggml/ggml-base directly (Windows import libs don't re-export transitive static-lib symbols).

    Black-box consumption contract

    The caller (ProvostXLLM) consumes this library ONLY through the engine/builder/factory facade surface; everything else in this repo is a CLOSED BLACK BOX to it. To make that consumable without leaking internals, three facade views live in csharp/Engines (pure delegation, no logic added):

    • StallWatchdogOps — sole construction seam for the stall-watchdog helper family; returns IPrefillStallDetector / IStallRecoveryLadder / IChunkWallClock (the ladder interface is csharp/Abstractions/IStallRecoveryLadder.cs; Implementation.StallRecoveryLadder implements it).
    • EngineMaintenance — file-level engine-bound maintenance (GGUF EOG/special-token metadata repair) without a loaded engine object in hand.
    • EngineLogging — process-wide native log routing (file sink / managed handler / level), previously reachable only via the Logging namespace. NOTE (BL-50): this is the DEBUG/llama.cpp stream — process-wide by nature (one specialist module owns the log state). For PER-ENGINE trails, use the audit surface below.
    • Per-engine audit + telemetry (ABI v9, BL-50) — consumer-relevant contract:
      • ModelConfig.AuditPath + AuditIncludePrompts at engine build time: each engine instance writes its OWN JSON-lines audit trail (lifecycle/operation events; never prompt text). Unconfigured = the feature is dead (one branch per commit, no I/O).
      • IGgufEngineOps.GetEngineTelemetry() — model-wide counter snapshot for THAT engine instance (EngineTelemetry record). Pull-based: derive rates between two snapshots in the caller. Per-lane detail remains on GetExecutorStats/GetConversationStats.
      • Two engines in one process → two independent audit files and two independent telemetry streams; nothing is shared (verified by Journey10's isolation leg).

    Effect: callers never reference Implementation, Interop, SafeHandles, or Logging namespaces at all. The native tree is untouched by this contract (the C API surface is unchanged). Decision.Engine.DecisionSessionFactory therefore constructs parameterless — the logger is a settable Logger property (quiet default) — so a facade-only caller's compiled metadata never drags the Logging namespace in (a ctor parameter's member-ref signature would do exactly that). No caller passes a logger through the ctor.
