    Namespace ProvostXInference.Decision.Engine

    Classes

    DecisionAssetCatalog

    Resolves the judge ASSET files (tokenizer.json, judge-spec-*.json) for one configured judge model. Resolution order (first hit wins): 1. model config "file" SIBLING directory (a bundled model dir ships both), 2. the server root's assets/models/judge/ directory, 3. next to the server binary (Assets/models/judge copied at build/pack time). Spec file per record kind: judge-spec-shell.json / judge-spec-process.json. Pure resolver — performs no IO beyond existence checks at Resolve time.

    DecisionHeaderReader

    Wave-2 ONNX header validation: a REAL protobuf scan of the ModelProto wire — ir_version (field 1, varint), the graph message (field 7) with its input (field 11) and output (field 12) ValueInfoProto names, and opset_import presence (field 8). Long initializers are SKIPPED by seek (never read into memory), so a 500MB+ model validates in milliseconds. Any structural violation throws — the load state machine maps that to fail-closed model_invalid before any session init is attempted. Wire-format reference: developers.onnxruntime.ai/onnx/proto (ModelProto, GraphProto, ValueInfoProto field tables). Pure scanner — no state.

    DecisionRecord

    One judged decision record, validated and normalized (parser → executor boundary). SHELL records carry command+cwd; PROCESS records carry the os/exe/chain/cmd/net/writes tuple. The untrusted SHELL "purpose" field deliberately has NO field here — it is echoed in audit logs only and never reaches decision input.

    DecisionSession

    ONE loaded ONNX judge model ready for batch inference: the ORT session (selected execution provider recorded), the tokenizer, the sequence spec, and the row collation + decode that mirrors the training evaluation exactly. Disposal releases the session. NOT thread-safe per instance beyond the session's own safety — the executor serializes inference per engine. Decode (training-eval semantics, per question row k = option count): choice → argmax over the k class logits → JudgeAction (allow/sandbox/deny); noul → softmax over 2, P(true) = NeedsSandbox; score → softmax over 5, expected value = Risk (0..4); confidence → max class probability after temperature scaling (0..1). The Jev raw wire (JudgeQuestionSet) decodes ARBITRARY caller questions instead: choice → argmax option label + per-option probabilities, score → expected level value + level-index probabilities, noul → P(true) — same softmax/temperature machinery, no escalation.

    DecisionSessionFactory

    Creates DecisionSessions for a judge model file: builds the ORT session options (full graph optimization, matching the training runtime) and walks the parsed ExecutionProviderChain in preference order (LLM-10 per-OS chains). EP FALLBACK RULE: a provider that fails to initialize (not bundled, driver/library problems, unsupported ops) degrades to the next entry — CPU is always the terminal fallback and is the only provider REQUIRED to work. The session's ACTUALLY-active provider is read back from the runtime (a silent ORT fallback to CPU counts as a fallback, not as GPU) and recorded so /pvx/health `active_execution_provider` is truthful. One factory per host; thread-safe (stateless beyond the injected option applier).

    DecisionTestSupport

    Test-support surface for the decision engine slice (Inference-side, consumed by both repos' test suites): opens an ORT session with ONE pinned provider. Keeping the only direct ORT-construction site inside ProvostXInference is the LLM→Inference extraction contract — LLM-side code references no ORT types.

    EpAttempt

    One candidate configuration for an EP session init: a label for diagnostics and the options mutation it applies. Ordered — first that successfully creates a session wins.

    ExecutionProviderChain

    Parsed execution-provider chain for a decision (judge) model (e.g. "cpu", "coreml->cpu", "cuda->cpu"). First entry is the preferred provider; later entries are fallbacks. Unknown names fail config validation loudly (the parser throws) — silent CPU fallback for typos is a misconfiguration hazard.

    ExecutionProviderOptionsApplier

    Per-EP session-option presets (LLM-10): each configured chain entry may need provider-specific session options (CUDA device id, DirectML device id, ROCm device id, OpenVINO device type, CoreML flags). Every preset list ends with a PLAIN name-append fallback so a quirk mismatch never fails an otherwise loadable provider — remaining failures fall down the chain to cpu (never fail when cpu works). Instance type, no state — cheap to construct, injectable.

    JudgeModelNotReadyException

    Typed fail-closed judge error: every judge endpoint maps this to HTTP 503 with a machine-readable code — NEVER to a 200/allow verdict. Codes: "model_unloaded" (judge engine present but not loaded) and "model_missing" (no judge model configured/registered for the requested id).

    JudgeNumericsGate

    Canonical numerics gate (LLM-10): before a NON-CPU execution provider is accepted, the judge model must reproduce the canonical wave-4 anchor (the destructive `dd` deny — recorded on the CPU EP: deny EXACT, conf ≈ 0.9231, risk ≈ 3.128) within tolerance. A GPU/CoreML EP that loads but drifts the anchors is REJECTED and the chain continues to the next provider (cpu always terminates). Fail-closed: gate evaluation errors count as drift.

    JudgeOption

    One rendered option of a judge question: its answer label and its criterion description (null = no description — rendered as the bare label). Option ORDER is decision-meaningful (argmax index → label). Pure data.

    JudgeQuestionAnswer

    ONE raw model answer for one Jev question (session decode → response mapper boundary). RAW semantics: the model's argmax choice / expected score / noul probability — NO risk-escalation rule applied (the escalation owner is JudgeVerdictMapper on the enriched arms; the raw wire stays raw). Field populations per type: choice → Choice + Confidence + Probabilities; score → Score + Confidence + Probabilities (level-index keyed) + Legend; noul → Noul. Pure data.

    JudgeQuestionAnswerSet

    The raw answers for ONE Jev request (one state), in question order, plus the USAGE inputs: the tokenized state length (actual tokenizer count of the serialized state — the usage.input_tokens definition) and the question count (the usage.output_tokens definition: one answer per question). Pure data.

    JudgeQuestionDef

    One typed judge question as trained (id, type, instructions, ordered options). Pure data — the judge spec carries these in the exact training order (action, needs_sandbox, risk_level).

    JudgeQuestionRowSet

    Encoded question rows for ONE Jev state + the pre-truncation token count of the serialized state (usage.input_tokens source). One row per question, in question order. Pure data.

    JudgeRowEncoding

    Encoded ONE question row of a judge record: token ids, marker (MASK) offsets, and the question's type. One record → one row per question, in question order. Pure data.

    JudgeScore

    Raw model output for one judged record (executor → response mapper boundary). The mapper owns the risk-escalation rule; the executor reports raw scores only.

    JudgeSequenceEncoder

    Builds judge model input rows from validated DecisionRecords: serializes the record EXACTLY as the training pipeline did (compact JSON with the mask token stripped), then assembles [CLS] {type} question: {instructions} [SEP] [MASK] opt0 [MASK] opt1 ... [SEP] {state} [SEP] per question, with the state tail capped to the sequence budget. Mirrors the training sequence builder (head budget 256, options capped at 48 tokens each) against the committed fixtures (Tests/Assets/judge/seq-fixtures.json). One encoder per judge model spec; thread-safe (stateless + immutable fields).

    JudgeSequenceSpec

    The FULL serialized inference specification for one judge model: record kind, sequence budget (max_len/head_max_len exactly as trained), the confidence temperatures fitted at export time, and the three typed questions in training order. Loaded from a spec JSON (Assets/models/judge/judge-spec-*.json) — the questions MUST match the training questions verbatim or the model scores text it was never trained on.

    JudgeStateQuestions

    One decision-engine question batch on the Jev wire: the SERIALIZED state text (rule owned by the server layer's state serializer — the engine plane only sees text) and the typed questions to answer. Questions = null → the judge's CANONICAL trained question set (the loaded session's spec — our additive default for omitted questions; real Jev requires questions). One request → one answer set. Pure data.

    JudgeTokenizer

    Deterministic BPE tokenizer for the Laya judge models (mmBERT vocabulary, HuggingFace tokenizer.json format: BPE model + Replace(" " → "▁") normalizer + Metaspace pre-tokenizer, add_special_tokens=False semantics — no BOS/EOS post-processing; the judge sequence builder places CLS/SEP itself). Pipeline (replicates the training tokenizer byte-for-byte): 1. added-token extraction (longest match, pre-normalization, per segment), 2. normalization: " " → "▁" per non-added segment, 3. Metaspace pre-tokenization: prepend "▁" when the segment does not start with it, then split BEFORE every "▁" (each "▁" begins a piece), 4. greedy lowest-rank BPE merges per piece (pairs of in-vocab symbols only), 5. unknown symbols: byte fallback ("<0xXX>" tokens), then <unk> (consecutive unknowns fused). Thread-safe: all mutable state is ConcurrentDictionary caches; encoding is a pure function of the input text. Deterministic: no RNG, no time, no IO after construction. Verified against the training pipeline on the committed vector fixture (Tests/Assets/judge/tok-vectors.json).

    OsExecutionProviderDefaultSource

    Per-OS default EP chains (LLM-10): macOS coreml→cpu, Windows directml→cpu, Linux cuda→rocm→openvino→cpu — first available wins at session init; cpu is always the terminal fallback. An injected osOverride keeps the mapping testable without touching the real host OS.

    Enums

    JudgeAction

    Judge verdict actions. The FINAL action in the wire response is produced by JudgeVerdictMapper, which owns the risk-escalation rule — the executor's raw action may be upgraded (allow → require_approval) but never downgraded.

    JudgeQuestionType

    Judge question types, numbered EXACTLY as the judge models were trained (laya QTYPES): choice=0, score=1, noul=2. The value feeds the model's qtype input — never renumber.

    JudgeRecordKind

    Discriminator for judge decision records on the decision-engine wire /v1/systemone (two record kinds on the same endpoint — the enriched arms; the raw Jev shape carries a free-form state instead).

    OnnxExecutionProvider

    Execution providers for decision (judge) models. The chain is parsed and validated at config time so unknown names fail loudly. Per-OS: CoreML (macOS), DirectML (Windows), CUDA/ROCm/OpenVINO (Linux) — cpu is always the terminal fallback.
